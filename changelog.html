1.5.02026-10-16

Added

  • Display outputs: show a dashboard page on other screens, such as the green room, without a second Mac (Settings → Displays, docs/display-outputs.md). Each output is pinned to its own page, is display-only, and can be sent three ways:
    • Full screen on a connected display: HDMI or USB-C into the video distribution system, a TV or a projector. It follows the display when it's unplugged and plugged back in, and never covers the main window's display.
    • To web browsers on the church network: a link (with a QR code) any TV browser, streaming stick, iPad or laptop can open. The page streams as MJPEG at 720p, 1080p, 4K or portrait, 1–15 fps, with a per-output access key, a single-frame mode for TVs that can't play MJPEG, and automatic reconnection. The links follow the Mac's address when it changes networks. Needs the web remote server on.
    • As an NDI source, through the NDI runtime installed by NDI Tools. Without it, Settings says so plainly.
  • Identify Displays and Stop All Display Outputs in the Layout menu.
  • Spotify integration. A new Spotify card shows what the Spotify app on this Mac is playing: artwork, title, artist, album, and a live playhead with elapsed and remaining time. It works locally through AppleScript, needs no Spotify account details, and never opens Spotify itself.
    • With Allow live control actions on (off by default):
      • Play/Pause, Next and Previous.
      • Drag the playhead to seek.
      • A volume slider.
      • Fade & Pause, which ramps the volume down over a set time (1–15 s, default 4), pauses, then restores the volume for the next song.
    • Simulated mode, a setup guide, a Settings section for the macOS Automation permission, and a Spotify line on the web remote.
    • Requires the Apple Events entitlement and usage description, both added to the app.
  • Page-grid dashboard views. Each view is now a grid you size yourself — any number of columns and rows from 1 × 1 to 32 × 32 — that always fills the dashboard, so a view works on a landscape, portrait or ultrawide monitor. Modules sit at exact cells, gaps are allowed, and they never overlap (see docs/ui-ux.md).
    • Free placement. Drag a module anywhere: one it covers swaps into the old slot or moves to the nearest free space; if something has nowhere to go, the outline turns red and the drop is refused. Resizing works the same way and stops at the module's minimum size — drag any edge or corner, so a module can grow left or up as well as right and down.
    • Multi-select. Click a module to select it, Shift- or ⌘-click to add more, ⌘A for all, Esc to clear. Dragging a selected module moves the whole selection as one block; resizing one resizes them all the same way, and a selected neighbour it grows into shifts over to make room.
    • Add on any empty cell. Hover an empty cell and click its +; the module lands there at its preferred size.
    • Right-click commands: Size (Minimum, Default, Wider, Narrower, Taller, Shorter, Fill Empty Space, Fill Page) and Move (Left, Right, Up, Down), also available to VoiceOver.
    • The top bar becomes the editor. Edit Layout (⌘E) turns the top bar blue in place — the dashboard no longer shifts down. It holds the view name, a Views menu (switch, new, duplicate, delete), Columns and Rows steppers (⌥⌘ + arrow keys), a rows ⇄ columns swap, grid presets with Double / Halve Density, Undo / Redo, Discard and Done. Shrinking the grid hides what doesn't fit, with an Undo notice.
    • A Layout menu with Edit Layout and More / Fewer Columns and Rows.
  • Modules scale with their size. Fonts and detail follow each module's size: the clock and SPL readouts grow, SPL + RTA goes side by side when wide, cue tiles fill their space, stream previews are the largest 16:9 that fits, timing and automations drop secondary sections when short, Shure lays mics in one row, and the Sermon Follower reads larger on wide modules. A module smaller than its minimum shows a compact tile: icon, name, and one live value (time, SPL, LIVE · viewers, overdue items, current slide).
  • Narrow windows. The window can be as small as 720 × 520; the top bar goes icon-only below 1280 pt and folds the service buttons into a menu below 960 pt.
  • Built-in SPL Meter (the primary SPL source; Smaart becomes the secondary one). Measures from a local audio input with A / C / Z weighting, Fast / Slow response, Leq and a 1/3-octave RTA. Calibrate with an acoustic calibrator (94 or 114 dB at 1 kHz); until then it honestly reads dB FS. One SPL source setting picks Built-in or Smaart for the SPL cards, and loudness warnings now apply to whichever is active (see docs/integrations/spl-meter.md).
  • MIDI Show Control send and receive in automations.
  • Timecode: a MIDI Timecode (MTC) output driven by a generator, time of day, or LTC from an audio input (an LTC → MTC converter), set up in Settings → Integrations → Timecode, plus a Timecode dashboard card (see docs/timecode.md).
  • Companion and HTTP automation devices alongside MIDI: press Bitfocus Companion buttons or set its variables, or send HTTP requests, from cues. Actions can be delayed (in milliseconds) after the cue fires, and pads show the Companion button they press.
  • Automations, with MIDI as the first protocol (see docs/automations.md).
    • Rules: when a plan item starts, timing starts/finishes, or a MIDI message arrives → fire a cue, fire the cue for the song's key, or run a command (Next Item, Key Up/Down, Re-send).
    • Song key map: 24 keys plus a no-key cue (e.g. Auto-Tune Off). Generate Key Cues… creates all 24 Program Change (or CC) cues in one go.
    • One master switch, off by default. Once on, automations work all the time; there's no arming. While it's off, item changes are logged as a dry run ("Not sent"). Pads and Test buttons work either way.
    • Devices (first in Tools → Automations): each has an output and an input port with its own Send / Receive switch, a health dot, activity lights and a Test button. Add Device is a protocol dropdown. Input rules only hear devices with Receive on.
    • Top-bar pill: "Automations Enabled" / "Automations Disabled", orange when an enabled device is offline; click for a popover with the switch, the last cue sent and device health.
    • Settings → Integrations → Automations: the master switch and Open Automations….
    • Per-item settings: a ⚡ chip on each Planning Center item shows what will fire; click it to override the cue (e.g. a "Bm" song that's really B mixolydian) or turn that item's automations off.
    • Cue Pads card (a launchpad of cues and commands) and an Automations card (enabled state, what fired, key ▲/▼, up next, activity).
    • Tools → Automations: devices, rules, cues, pads, a MIDI monitor with Learn and test input, and the activity log.
  • MIDI integration (CoreMIDI): output to any port, input from all ports, hot-plug, simulated mode. Always on; the Automations switch and each device's Send/Receive switches gate it.
  • Service reports by email. When a service's timing finishes, its report can be emailed: a dark, card-based summary in ProductionDeck's design language. It shows how the service landed against the plan, a short story of the run, total/planned time, service loudness and peak, and every item with its planned vs actual time, a ± pill, a progress bar and its levels. A plain-text version is included and the CSV is attached. Set it up in the new Settings → Email tab (Gmail, iCloud Mail or any SMTP server; SSL/TLS or STARTTLS; password kept in the Keychain), with Send Test Email and a Simulate mode that saves to an Outbox folder. Reports that can't be sent (offline booth Mac) retry for up to a day. Service Reports gains Preview Email and Email Report.

Existing views are converted automatically to page grids that look like they did (for example, Pre Service becomes 10 × 10 with the Shure mics across the top). The old dashboard.json is left untouched as a backup and never written again, so an older build can't overwrite the new layouts. 1.3.22026-09-06

Changed

  • Sermon Follower now understands nearby paraphrases. Its proven keyword matcher remains the authority for stated points, scripture, and large skips, while an on-device sentence model can advance to one of the next two blocks when Josh keeps the manuscript's meaning but changes nearly all of its words. Semantic movement requires a complete thought, a clear lead, and repeated recognition results; it cannot launch the highlight into a distant, vaguely related section. Fixed

  • Shure mic cards actually say "Off" now. The previous attempt watched for receiver reports that ULX-D hardware never sends (TX_STATUS and RX_TX_CONNECTION are not in Shure's spec, and TX_AVAILABLE is a battery- charger command meaning "docked"), so a card kept showing the last RF and battery reading after its mic was switched off. It now reads the real signals — TX_TYPE UNKN, the documented TX_OFFSET 255, and a squelched XX antenna field in the metering stream — and holds the squelch signal for about three seconds so a momentary dropout doesn't flash the card. The last values are hidden rather than thrown away, so a mic that comes back on shows its reading immediately. Mock mode now cycles a channel off so the state can be checked without a receiver.
  • Following stays continuous across speech-recognition restarts. The recent 40-word window now carries across Apple's 45-second recognition segments without duplicating partial-result words. Late callbacks from a finished segment can no longer recycle the new recognizer, and Reset starts a clean segment so old speech cannot immediately restore the previous highlight.

1.2.72026-07-19

Fixed

  • Sermon Follower: fewer occasional launches to the wrong section. The follower now blocks a far jump while the current block still clearly matches — a real skip only fires once he's actually moved off the current point (its score has decayed). 1.2.62026-07-19

Fixed

  • Sermon Follower stops jumping to random paragraphs. With the freeze gone (1.2.5) the remaining problem was visible: noisy recognition would occasionally mis-hear a word that happens to be distinctive to some unrelated paragraph, spiking that block's score and flinging the highlight there, then somewhere else. A far jump now requires several distinct corroborating words shared with what's being said (not just one), a larger sustained lead, and the "easy" near-zone is tighter — so a single stray word is ignored while a genuine skip (many matching words) still catches up. 1.2.52026-07-19

Fixed

  • Sermon Follower freeze root-caused and fixed. The diagnostic build (1.2.4) caught it: the on-device recognizer was ending segments with kAFAssistantErrorDomain code 1110 ("no speech detected"), and the old recovery reused the same SFSpeechRecognizer — which stays wedged once it errors and just throws 1110 again, a silent loop that produces no words, so the highlight froze. Recognition errors now recreate the recognizer (with a short backoff), and repeated errors escalate to a full audio-engine restart in case audio has stopped reaching it. The follow self-heals instead of freezing; the block cursor persists.

1.2.32026-07-12

Fixed

  • Sermon Follower: no more wild jumping, and a real fix for the freeze. v1.2.2's global re-anchor was too eager — with noisy live recognition it flung the highlight all over the document. The matcher is rebuilt around one stable rule: a single smoothed score per block plus distance-graded movement — a nearby paragraph takes the highlight on a small, brief lead (responsive normal reading), while a far jump needs a large, sustained lead (so noise can't fling it across the page, but a genuine skip still catches up). Discriminative weighting (for telling similar altar-call paragraphs apart) is now folded into the block profiles so it's stable, not recomputed per update.
  • Recognition no longer freezes mid-sermon. The underlying freeze was the on-device speech recognizer quietly going silent after ~a minute (a known SFSpeechRecognizer limit), which the matcher couldn't do anything about. Added a capture watchdog: if speech-level audio is still arriving but no recognition results come for several seconds, it recreates the recognizer and restarts; if audio stops entirely, it restarts the engine. Ordinary silence never triggers a reset, and the highlight position is preserved across a reset.

1.2.22026-07-12

Fixed

  • Sermon Follower no longer freezes mid-sermon. With the v1.2.1 anti-flicker stickiness, if the follower fell behind by more than its look-ahead window, the paragraph the speaker was actually on fell outside the candidate range, so it could never catch up — the highlight locked in place and stopped moving. The follower now runs a cheap coarse match across the whole document every update and, when a block well outside the neighborhood clearly out-scores the current one for several updates running, re-anchors to it. The cursor can no longer get stuck behind the speaker.
  • Less sticky / quicker to keep up. Widened the catch-up look-ahead, lowered the switch margin, and made the score smoothing more responsive, so the highlight advances to the next paragraph sooner while still resisting momentary flicker.

1.2.12026-07-12

Fixed

  • Sermon Follower no longer flip-flops between similar adjacent paragraphs (e.g. during an altar call, where several paragraphs repeat the same refrain with small variations). Plain cosine similarity scored those near-duplicate blocks almost equally — the shared words dominated — so the highlight bounced between them. The follower now scores discriminatively: among the blocks near the cursor, each shared word's weight is divided by how many of those blocks contain it, so the words that differ between the similar paragraphs decide which one is active. It also smooths scores over time (a challenger must lead the current block by a margin across several updates before the highlight moves, so a momentary match can't cause a jump) and weights recent words more heavily, so it tracks the paragraph being spoken now rather than one still lingering in the window. Still fully on-device.

1.2.02026-07-12

Changed

  • Sermon Follower now follows the outline by paragraph block, not word-for-word. The old matcher chased exact 2–4 word phrases, so it stalled or sat on a single word whenever the preacher paraphrased or ad-libbed. The whole active block is now highlighted (finished blocks dim, upcoming blocks normal) instead of a single word.

Fixed

  • Sermon Follower stops jumping around on repeated or ad-libbed words. The matcher was treating any recognized phrase as a command to relocate the cursor, so a word the speaker repeated (but that's only written a couple of times, e.g. "bedrock") kept yanking the highlight to one of those written spots. The aligner is redesigned around continuity: it now tracks contiguously — advancing in small steps as the speaker reads and simply ignoring anything it can't place nearby (ad-libs no longer move it) — and only makes a larger jump (catch-up, skip, or recovery) on a unique, exact 4-word phrase. A phrase that appears more than once in the script is ambiguous and never relocates the cursor, and a backward jump happens only after a sustained stall (recovering from a bad jump), so a one-off reference to earlier text can't drag it back. A follow-up iteration will add a confidence-scored multi-candidate tracker for even better handling of duplicated phrases and noisy recognition.

1.1.42026-07-05

Fixed

  • Sermon Follower no longer freezes near the top while the speaker is well into the message. The matcher only searched a bounded distance ahead of the cursor, so once the speaker got further ahead than that window (e.g. after an early stall), the phrase was never in range and the highlight stayed stuck at the top. The aligner now: (1) catches up — a 4-word exact phrase matching far ahead jumps the cursor straight there; (2) caps weak jumps — a generic 2-word phrase can't leap across the document to a coincidental match; and (3) re-anchors when stalled — after several non-matching updates it snaps to the nearest occurrence of a specific phrase anywhere in the script, recovering from a cursor that was jumped past the real reading position. Previously the matcher was forward-only and could be stranded in either direction.

1.1.32026-07-05

Fixed

  • Sermon Follower no longer drops words at sentence boundaries. On-device speech recognition runs in segments (recycled on a timer and whenever it finalizes, which happens on nearly every pause). The old segment recycle nil'd the audio request before creating the next one, so audio arriving in that gap — the first words after each pause, and across the ~45s roll — was lost and never reached the matcher, causing the highlight to skip phrases the speaker read verbatim. Segment swaps are now gapless: the new recognition request starts receiving audio before the old one is closed. Added a redacted stall diagnostic (word counts only, never transcript text) under Console filter SpeechFollower to help diagnose any remaining tracking gaps.

Fixed
