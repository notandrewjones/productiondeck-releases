1.5.02026-10-29

The first release since 1.4.3, including everything from the 1.5.0 betas. Facebook sign-in through ProductionDeck's own Meta app arrives in a later update, once Meta approves the app; until then you can connect your own Meta app in Facebook's settings, under Advanced.

Added

  • Reminders. Put a message on screen for the operator at the right moment: at a timecode, when a ProPresenter slide or group goes live, when a plan item starts (or a set time into it), with time left in an item, before the service starts, at a clock time, when timing starts or finishes, or when a MIDI, MSC or OSC message arrives. Reminders float over the top of the window without moving anything, newest on top, and can flash three times. STANDBY counts down to ones whose time is known. Acknowledge with Done or ⌘↩. Send reminders to channels (Booth, Audio, Stage…) and choose which channels the main window, each display output and the web remote show. A Reminders module lists what's up and what's next. Right-click a slide, a plan item or the Timecode card to add one. Each reminder fires in every plan, in every plan of one service type (Sunday, not Wednesday), or only in one plan (this week's cues). Copy last week's reminders to this plan in one click, and clear old plans' reminders in one step. Set up in Tools → Reminders; nothing is sent to other gear.
  • Web Embeds. Put your own web page or online chat in a dashboard module. Save each page once in Settings → Web Embeds, then add it to any view from Edit Layout. Each embed is sandboxed: it can't reach other modules, your integrations or files on this Mac, can't open windows, download files or use the camera, and a link to another site opens in your browser. HTTPS is required unless you turn on Allow HTTP for that embed (the module then says NOT SECURE). Sign-ins are kept between launches, and Sign Out clears them. The module says when a page is loading, retrying or blocked, and why. Embeds stay on this Mac: never on display outputs or the web remote.
  • Problem reports in Livestream Chat. Messages where a viewer reports a stream problem ("can't hear", "no sound", "buffering", "frozen") are tinted orange with a chip saying AUDIO or VIDEO. A chip above the chat counts the last 10 minutes and jumps to the latest one. A compact chat module shows that count instead of the newest message. Add your own phrases on any chat platform's Settings page. Matching happens on your Mac.
  • Timecode triggers for Planning Center items. Right-click an item → Add Timecode Trigger… and type a timecode (or Use Current). When the timecode source (LTC input, the generator or time of day) plays through it, the item starts as if you'd chosen Start Timing Here, and its automations (the cues on its chip) fire. Items with a trigger show it as a chip; click to change it.
  • Timecode triggers for cues. The cue editor, in Automations and on pads, has a Timecode row: add as many timecodes as you like (type one, or Add Current), and the cue fires each time the timecode plays through one, with automations enabled. The cue library and pads show them. Settings → Timecode → Timecode triggers turns item and cue triggers off without losing them.
  • ProductionDeck Mail. Service report email no longer needs your own mail server. Turn on email in Settings → Email, add recipients, and reports come from "Your Church via ProductionDeck". This is included with your subscription. Each recipient confirms once by email, and every report has an unsubscribe link. Settings shows who has confirmed and can resend the link. Replies go to an optional Reply-To address. Your own SMTP server is still available under Advanced… → Use a custom email server, and existing SMTP setups are unchanged. Reports sent this way pass through our mail service and Resend: see the updated privacy policy.
  • OSC in Automations. Cues and pads can send OSC; incoming messages can trigger rules. Add any OSC app or console by host, port and transport and send any address you like; optional presets for common lighting, audio and show/media apps fill in the port and setup steps and add ready-made commands. Includes an input monitor and Learn, input monitor and Learn, Bonjour discovery, and an off-by-default UDP/TCP listener with an allow-list and rate limits.
  • In-app updates. ProductionDeck checks for a new version once a day (and when you choose ProductionDeck → Check for Updates…), shows what's new, and installs it when you click Install Update, then relaunches. It never interrupts a service: an update found while the service timer is running only shows a small blue icon in the top bar, and Install and Relaunch during a service offers to install when you quit instead. Settings → General → Updates shows the version and last check, and turns automatic checks off. Updates are signed and verified before they install. The check downloads the update list from updates.productiondeck.io (hosted by GitHub) and sends no identifiers or system details. Copies older than this version need one last manual install from the DMG.
  • Dialogs match the app's dark look. The update window and app alerts are now dark, like the rest of ProductionDeck, even when macOS is in light mode.
  • Checklists follow the Planning Center plan. Each plan gets its own checklist, and switching plans in the top bar switches the checklist. Check-offs stay with their plan, so the 9:00 and 11:00 services are tracked separately. Choose a template for each service type under Checklists → Planning Center. Items can now be due a set time before or after the service start, which uses each plan's service time. The checklist's picker lists every plan, so you can prep next week's checklist without changing the dashboard. With Planning Center off, checklists work as before.
  • Choose which Planning Center service types load. Settings → Planning Center → Service types. Plans from every checked type appear together in the plan navigator and checklists. Until you choose, the first service type loads, as before.
  • License keys. ProductionDeck now asks for the license key from your subscription. Paste it once per Mac; Polar emails a link to it after you subscribe. The app checks the key with Polar (sending only the key and ProductionDeck's organization ID) at launch and once a day, keeps working offline for 14 days between checks, and never interrupts a running service: a lapsed or revoked key only shows a dismissible notice and is asked about at the next launch. Settings → License shows the status and lets you change or remove the key. Your layouts, settings and data are never touched.
  • Shure receivers can be found automatically. Settings → Shure → Receivers has a new Find Receivers button that scans this Mac's networks for Shure receivers (ULX-D, QLX-D, SLX-D, Axient Digital) on port 2202 and lists each one with its name, model, firmware, IP, and MAC. Add one in a click, or add all new ones at once. A receiver that's already set up but whose DHCP address changed shows Update IP. The scan only asks receivers who they are; it never changes their settings.
  • Display outputs: show a dashboard page on other screens, such as the green room, without a second Mac (Settings → Displays, docs/display-outputs.md). Each output is pinned to its own page, is display-only, and can be sent three ways:
    • Full screen on a connected display: HDMI or USB-C into the video distribution system, a TV or a projector. It follows the display when it's unplugged and plugged back in, and never covers the main window's display.
    • To web browsers on the church network: a link (with a QR code) any TV browser, streaming stick, iPad or laptop can open. The page streams as MJPEG at 720p, 1080p, 4K or portrait, 1–15 fps, with a per-output access key, a single-frame mode for TVs that can't play MJPEG, and automatic reconnection. The links follow the Mac's address when it changes networks. Needs the web remote server on.
    • As an NDI source, through the NDI runtime installed by NDI Tools. Without it, Settings says so plainly.
  • Identify Displays and Stop All Display Outputs in the Layout menu.
  • Spotify integration. A new Spotify card shows what the Spotify app on this Mac is playing: artwork, title, artist, album, and a live playhead with elapsed and remaining time. It works locally through AppleScript, needs no Spotify account details, and never opens Spotify itself.
    • With Allow live control actions on (off by default):
      • Play/Pause, Next and Previous.
      • Drag the playhead to seek.
      • A volume slider.
      • Fade & Pause, which ramps the volume down over a set time (1–15 s, default 4), pauses, then restores the volume for the next song.
    • Simulated mode, a setup guide, a Settings section for the macOS Automation permission, and a Spotify line on the web remote.
    • Requires the Apple Events entitlement and usage description, both added to the app.
  • Page-grid dashboard views. Each view is now a grid you size yourself — any number of columns and rows from 1 × 1 to 32 × 32 — that always fills the dashboard, so a view works on a landscape, portrait or ultrawide monitor. Modules sit at exact cells, gaps are allowed, and they never overlap (see docs/ui-ux.md).
    • Free placement. Drag a module anywhere: one it covers swaps into the old slot or moves to the nearest free space; if something has nowhere to go, the outline turns red and the drop is refused. Resizing works the same way and stops at the module's minimum size — drag any edge or corner, so a module can grow left or up as well as right and down.
    • Multi-select. Click a module to select it, Shift- or ⌘-click to add more, ⌘A for all, Esc to clear. Dragging a selected module moves the whole selection as one block; resizing one resizes them all the same way, and a selected neighbour it grows into shifts over to make room.
    • Add on any empty cell. Hover an empty cell and click its +; the module lands there at its preferred size.
    • Right-click commands: Size (Minimum, Default, Wider, Narrower, Taller, Shorter, Fill Empty Space, Fill Page) and Move (Left, Right, Up, Down), also available to VoiceOver.
    • The top bar becomes the editor. Edit Layout (⌘E) turns the top bar blue in place — the dashboard no longer shifts down. It holds the view name, a Views menu (switch, new, duplicate, delete), Columns and Rows steppers (⌥⌘ + arrow keys), a rows ⇄ columns swap, grid presets with Double / Halve Density, Undo / Redo, Discard and Done. Shrinking the grid hides what doesn't fit, with an Undo notice.
    • A Layout menu with Edit Layout and More / Fewer Columns and Rows.
  • Modules scale with their size. Fonts and detail follow each module's size: the clock and SPL readouts grow, SPL + RTA goes side by side when wide, cue tiles fill their space, stream previews are the largest 16:9 that fits, timing and automations drop secondary sections when short, Shure lays mics in one row, and the Sermon Follower reads larger on wide modules. A module smaller than its minimum shows a compact tile: icon, name, and one live value (time, SPL, LIVE · viewers, overdue items, current slide).
  • Narrow windows. The window can be as small as 720 × 520; the top bar goes icon-only below 1280 pt and folds the service buttons into a menu below 960 pt.
  • Built-in SPL Meter (the primary SPL source; Smaart becomes the secondary one). Measures from a local audio input with A / C / Z weighting, Fast / Slow response, Leq and a 1/3-octave RTA. Calibrate with an acoustic calibrator (94 or 114 dB at 1 kHz); until then it honestly reads dB FS. One SPL source setting picks Built-in or Smaart for the SPL cards, and loudness warnings now apply to whichever is active (see docs/integrations/spl-meter.md).
  • MIDI Show Control send and receive in automations.
  • Timecode: a MIDI Timecode (MTC) output driven by a generator, time of day, or LTC from an audio input (an LTC → MTC converter), set up in Settings → Integrations → Timecode, plus a Timecode dashboard card (see docs/timecode.md).
  • Companion and HTTP automation devices alongside MIDI: press Bitfocus Companion buttons or set its variables, or send HTTP requests, from cues. Actions can be delayed (in milliseconds) after the cue fires, and pads show the Companion button they press.
  • Automations, with MIDI as the first protocol (see docs/automations.md).
    • Rules: when a plan item starts, timing starts/finishes, or a MIDI message arrives → fire a cue, fire the cue for the song's key, or run a command (Next Item, Key Up/Down, Re-send).
    • Song key map: 24 keys plus a no-key cue (e.g. Auto-Tune Off). Generate Key Cues… creates all 24 Program Change (or CC) cues in one go.
    • One master switch, off by default. Once on, automations work all the time; there's no arming. While it's off, item changes are logged as a dry run ("Not sent"). Pads and Test buttons work either way.
    • Devices (first in Tools → Automations): each has an output and an input port with its own Send / Receive switch, a health dot, activity lights and a Test button. Add Device is a protocol dropdown. Input rules only hear devices with Receive on.
    • Top-bar pill: "Automations Enabled" / "Automations Disabled", orange when an enabled device is offline; click for a popover with the switch, the last cue sent and device health.
    • Settings → Integrations → Automations: the master switch and Open Automations….
    • Per-item settings: a ⚡ chip on each Planning Center item shows what will fire; click it to override the cue (e.g. a "Bm" song that's really B mixolydian) or turn that item's automations off.
    • Cue Pads card (a launchpad of cues and commands) and an Automations card (enabled state, what fired, key ▲/▼, up next, activity).
    • Tools → Automations: devices, rules, cues, pads, a MIDI monitor with Learn and test input, and the activity log.
  • MIDI integration (CoreMIDI): output to any port, input from all ports, hot-plug, simulated mode. Always on; the Automations switch and each device's Send/Receive switches gate it.
  • Service reports by email. When a service's timing finishes, its report can be emailed: a dark, card-based summary in ProductionDeck's design language. It shows how the service landed against the plan, a short story of the run, total/planned time, service loudness and peak, and every item with its planned vs actual time, a ± pill, a progress bar and its levels. A plain-text version is included and the CSV is attached. Set it up in the new Settings → Email tab (Gmail, iCloud Mail or any SMTP server; SSL/TLS or STARTTLS; password kept in the Keychain), with Send Test Email and a Simulate mode that saves to an Outbox folder. Reports that can't be sent (offline booth Mac) retry for up to a day. Service Reports gains Preview Email and Email Report.

Changed

  • Cue Pads is now Hot Buttons. In a worship booth "pads" usually means ambient synth pads, and the card also fires commands and ProPresenter slides, not only cues. Each one is a button ("Button 3", "Clear Button", "Add to Hot Buttons"), and Tools → Automations → Cues & Pads is now Cues & Buttons. Library rows show a small grid badge with the button number instead of "P3". Your buttons, layouts and settings carry over unchanged.
  • Hot Buttons card: one status word, steadier grid. The card's corner says whether a press will work (Ready, Locked, MIDI disconnected, No devices, Slides off) instead of always reading CONNECTED, and the lock sits beside it. MIDI only counts when you have a MIDI device. Notices lay over the bottom of the grid, so buttons no longer move after a click. Small cards switch to short, label-only buttons before they scroll, and a scrolling card says how many buttons are out of sight. Hyphenated names ("Walk-in") no longer break at the hyphen.
  • Hot Buttons say whether a press worked. A button still flashes when you press it, then shows what happened: a small check once it sent (until you press another), or Didn't send in red with a notice saying why ("Sending to “SuperRack” is off", "“USB” isn't connected"). Before, a press looked the same whether or not anything went out, and the reason was only in Activity. Slide presses now appear in Activity too.
  • The Hot Buttons card is for firing, not editing. Clicking an empty button opens the small chooser from Tools → Automations (New Cue, a library cue, a command) instead of a large editor over the dashboard, and does nothing but say so while the card is locked. Right-click → Edit in Automations… opens that button in Tools → Automations. Delete Cue… is no longer in the card's right-click menu (it's still on the board). Empty slots stay a faint outline until you point at one, and a slide that's live says LIVE in its caption instead of only turning the edge green.
  • Livestream Chat redesign. Messages are flat rows with hairline dividers instead of bubbles, so about twice as many fit. Text scales with the module, so a large chat module (or one on a green-room display) reads from across the room. YouTube and Facebook messages carry their logos instead of "YT" and "FB" boxes. The same person posting the same words on two platforms shows as one message with both logos. New messages slide in, and a new problem report starts bright and settles (fades only, with Reduce Motion on).
  • Custom Chat is only in the owner's copy. Customer copies show YouTube and Facebook chat, read-only. Posting from the chat card now has its own switch, off by default.
  • Cues & Pads is one board. Tools → Automations → Cues & Pads shows the cue library, the pads (drawn like the dashboard card) and the inspector side by side, with no more Cues | Pads switch. Drag a cue or command from the library onto a pad; dropping on a full pad replaces it, and ⌘Z undoes it. Click an empty pad for New Cue, a library cue or a command. A cue started there goes on that pad when you add it. Click a pad to edit its cue, with Remove from Pad at the top. Library rows show their pads (P3) and an "Add to next empty pad" button on hover. A search field replaces the On Pads / Not on Pads filter. The cues Song Keys fires fold into one group. With no devices set up, one note replaces "→ No device" on every row; otherwise a red mark flags only cues with an action that has no device.
  • Cues & Pads board refinements. The board keeps four pads to a row, so pads never move. Where the window has room, the inspector is always open beside the board (it reads Nothing selected when empty, and has no close button); the library narrows to make that room on smaller windows, and only windows too narrow for all three slide the inspector over the board. Choosing fewer pads asks before removing pads that have something on them, and ⌘Z brings them back. A cue pad with an action that has no device says No device on the board and the dashboard card, and the action's Send to is outlined in orange; the Cue Pads card reads NO DEVICES when none are set up. Selected pads get a ring outside the pad, and the pad under a drag says Place, Replace or Swap. Empty pads read Empty. Place on Pad (row right-click and the cue's ⋯ menu) puts a cue or command on a chosen pad, and the arrow keys and Delete work on the board. The cue inspector's subtitle is now "2 actions · On pads 2, 6".
  • Song Keys is one page, always open. No more key-map list or Add Key Map: Tools → Automations → Song Keys shows the 24 keys with a cue picker each, ready to fill in. Nothing fires until you first click Save. Key maps from earlier builds beyond the first are listed with a Remove button.
  • Custom song keys. Add key text Planning Center uses that the 24 keys don't cover (such as "B mixolydian" or "G - A") and pick its cue. It matches the song's key as Planning Center shows it, ignoring capitals, spacing and ♯/♭, and takes priority over the 24 keys. "From this plan" buttons add the current plan's key names exactly as Planning Center sends them.
  • Facebook Live sign-in, rebuilt. Click Connect Facebook, enter the code ProductionDeck shows at facebook.com/device, and share your church's Page; then choose the Page in Settings (it's picked for you when you share one). Nothing to register: release builds sign in through ProductionDeck's own Meta app once Meta approves it, and your own Meta app moves under Advanced (App ID and Client Token; the App Secret is no longer used). The dashboard now reads the Page with a Page token that doesn't expire, so it keeps working past the 60-day sign-in. Disconnect now removes ProductionDeck's access on Facebook too. Uses Graph API v26.0 (v19.0 was retired), handles Facebook's invalid-token and rate-limit errors properly, and no longer requests commenters' profile pictures. If you used your own Meta app, enter its Client Token under Advanced and connect again.
  • ProPresenter no longer starts Service Timing. Timing starts only at the plan's service time or when you press Start (or Start Timing Here), so running slides during rehearsal can't start the service clock. Once timing is running it still follows ProPresenter from item to item. If you start timing by hand before the service time, your start is kept when the clock reaches it. The Start Automatically from ProPresenter option is gone.
  • Service Timing is part of the Planning Center card. The countdown, progress, live loudness, and Start / Next Item / Finish controls now sit at the top of the Planning Center card, with the run of service scrolling beneath them. The timer is smaller than the old card's so the plan stays in view, and it folds to a single line when the card is short. Service Reports are in the timing ⋯ menu. Saved views with the old Service Timing card show the Planning Center card in its place (one per view), and the Sermon view gives the combined card a full-height column.
  • One Livestream Chat card for every platform. Custom chat, YouTube, and Facebook messages now share one card in the custom chat's design, each badged TV / YT / FB when more than one platform is on. The compose row posts to the custom chat, and moderation still works on custom-chat messages; YouTube and Facebook stay read-only. Saved views with the old Live Chat (All Platforms) card show the Livestream Chat card in its place.
  • Smaller, square Shure mic tiles. Each mic is now a square tile with the person's photo, name, battery, and RF bars, plus a battery-level bar along its bottom edge (amber when low). Tiles fill the module from top to bottom at any size, and their text and photo grow on big modules. When there are too many mics for squares to fill the height, tiles grow taller instead. The Shure module now fits two rows of a 10 × 10 page; it needed three before.
  • Licensing. ProductionDeck is now proprietary, closed-source software sold by paid subscription, one subscription per physical campus. The MIT license and open-source contribution files are removed; see LICENSE and EULA.md. Versions released before this change remain available under the MIT License to those who received them.
  • YouTube connects in one click. Choose "Connect YouTube Account", pick your Google account in the browser, and allow read-only access. There's no Google Cloud project to create and no Client ID or Secret to paste: release builds include ProductionDeck's own Google OAuth client. Settings shows which channel is signed in, and Disconnect now revokes ProductionDeck's access at Google instead of only forgetting it on this Mac. If access is removed from the Google Account page, ProductionDeck notices and shows YouTube as disconnected. Settings links to the YouTube Terms of Service, the Google Privacy Policy, and Google's access settings. Anyone who wants their own YouTube API quota can still use their own Google Cloud client under Advanced; installs already connected that way keep working.
  • YouTube uses far less API quota. While live, broadcast details refresh every 30 seconds instead of on every chat poll; with nothing live, ProductionDeck checks for a broadcast once a minute. When the daily quota runs out, the card says so and retries in 15 minutes instead of claiming the sign-in expired, and a broadcast whose chat ended no longer reads as a sign-in problem.
  • Settings has a new look. One sidebar now lists every page (General, Web Remote, Displays, Email, then each integration with its live status dot), replacing the tabs and the separate Integrations list. Each page opens with a header naming it, a short description, and, for integrations, the Setup Guide and current status. Settings are grouped into the same dark rounded cards as the dashboard, on/off settings are switches, and the window's dark background now runs to the top edge. Displays shows a hint when there are no outputs yet, and Email's recipients field is labeled "Send to".
  • Planning Center connects in one click. Choose "Connect with Planning Center", sign in in the browser, and approve. There's no OAuth app to register and no Client ID or Secret to paste: ProductionDeck now ships with its own public Planning Center app and uses PKCE, so no secret is involved. Installs that connected with their own OAuth app keep working until they reconnect, which moves them to the built-in app. Planning Center's official logo now sits at the top of its settings page.
  • Resi setup is a step-by-step wizard. Resi's settings page now walks through four pages: what the integration does and what you need, creating an API client in Resi Studio (with an Open Resi Studio button), pasting the Client ID and Secret, and testing them. A test signs in and lists how many encoders and destination groups Resi returned, without starting or stopping anything. When something is wrong, it says what: a Client ID that isn't in Resi's format, rejected credentials, an API client missing the Go Live API role, a plan without API access, or no encoders. Once credentials are saved, the page shows your Resi account's status, then optional cards for the Go Live target, live status for Studio events (manifest URL or schedule ID), the stream preview, and live control.
  • Web remote: who can see it. Settings → Web Remote now says plainly that anyone on the network can open the status page, and lists what it shows. Turn on Require a key in the link to allow only links with the key. Copy the link or scan its QR code, and use New Key… to replace it. Display outputs keep their own links. Status messages on the page no longer include device addresses.
  • Saved layouts move to dashboard-pages.json. Existing views are converted automatically to page grids that look like they did (for example, Pre Service becomes 10 × 10 with the Shure mics across the top). The old dashboard.json is left untouched as a backup and never written again, so an older build can't overwrite the new layouts. A layouts file that can't be read is copied aside before anything replaces it, and one damaged view no longer resets the others.
  • The three-column layout with its header band, column dividers and single-card columns is replaced by page grids.
  • The web remote server now answers only its known routes (404 otherwise, 405 for non-GET requests) and drops connections that send nothing for 10 s. It restarts by itself if a network change stops it.
  • Settings text fields no longer write back an unchanged value as they disappear, which could undo a change made in the meantime.
  • Release builds relax library validation so the installed NDI runtime can load; only a root-owned, protected runtime is ever loaded (docs/security.md).

Fixed

  • Livestream Chat stopped following new messages after switching views, and its "new messages" pill covered the newest message. It now stays on the newest message until you scroll up, counts every message you missed, and shows the count in a bar under the chat.
  • A chat message that failed to send disappeared without a word. The text now stays in the box until it posts, and the card says why it didn't.
  • Two quick chat moderation actions: the second was silently dropped while the card said it worked. It now waits its turn.
  • Failed saves are shown, not just logged. If ProductionDeck can't save dashboard layouts, checklists, integration settings, mic profiles, Quick Cues, display outputs, automations, service history or email settings (a full disk, a read-only folder), a banner at the bottom of the window says what didn't save, with Retry and Show in Finder. A Keychain refusal for an integration password asks you to enter it again. The banner never interrupts a service, and Diagnostics → Export lists the failures.
  • Modules no longer leave an extra gap at the bottom. Content that fills its module, like the SPL footer and the clock, now reaches the bottom padding instead of stopping 10 points short.
  • The YouTube Live preview plays again. YouTube now refuses to play embedded videos inside apps that don't identify themselves, showing "Video player configuration error" (Error 153) on the card. ProductionDeck now identifies itself to the YouTube player, so the muted preview plays.
  • YouTube shows 0 viewers instead of "Unavailable". YouTube leaves the viewer count out entirely while nobody is watching, which the card read as unknown. A live broadcast with no reported count now shows 0.
  • Wrong Resi credentials no longer show as "Cannot reach Resi". Resi answers a bad Client ID or Secret with HTTP 400, so the dashboard reported a network outage. It now says the credentials were rejected. An API client missing the Go Live role now says access was denied.
  • Facebook and YouTube previews say why they're blank. When the preview couldn't play, the card said "Preview unavailable on this Mac", which is wrong on current macOS. The usual cause is a broadcast that isn't public, such as a Facebook admin-only test stream: the embedded players can only show public videos (YouTube: public or unlisted). The card now says that.
  • The web remote now HTML-escapes every value it shows.

Removed

  • Quick Cues. Its job moved to Hot Buttons: drag a slide, a presentation (fires its first slide) or a media entry from the ProPresenter card onto a button, and click it to fire it, whatever is live, just as Quick Cues did. The live slide's button is outlined in green, wide buttons show the slide's preview, and Edit… sets the button's label and color. Slide buttons follow the Hot Buttons lock and need ProPresenter's Control setting. Your saved Quick Cues move onto empty buttons (buttons are added if they're full), and a view that had the Quick Cues card shows Hot Buttons in its place.
  • Planning Center Personal Access Tokens. Connect with Planning Center is now the only sign-in. An install that used a token shows Planning Center as not connected until someone clicks Connect, which also deletes the old token from the Keychain.
  • Sermon Follower. The Google Docs sermon follower, its Google sign-in, and the on-device speech recognition that tracked the sermon are gone, along with the speech-recognition permission. The built-in Sermon view now shows ProPresenter and Service Timing in its place. A saved view that had the Sermon Follower module still loads, without that module.
  • Vimeo Livestream. The Vimeo card, sign-in, and settings are removed (Vimeo has no public live-chat API). YouTube and Facebook are unchanged.
  • Leftover Google Docs and Vimeo sign-in tokens are deleted from the Keychain the next time ProductionDeck loads its saved credentials.

1.2.32026-07-12

Fixed

  • Sermon Follower: no more wild jumping, and a real fix for the freeze. v1.2.2's global re-anchor was too eager — with noisy live recognition it flung the highlight all over the document. The matcher is rebuilt around one stable rule: a single smoothed score per block plus distance-graded movement — a nearby paragraph takes the highlight on a small, brief lead (responsive normal reading), while a far jump needs a large, sustained lead (so noise can't fling it across the page, but a genuine skip still catches up). Ordinary silence never triggers a reset, and the highlight position is preserved across a reset.

1.2.22026-07-12

Fixed

  • Sermon Follower no longer freezes mid-sermon. With the v1.2.1 anti-flicker stickiness, if the follower fell behind by more than its look-ahead window, the paragraph the speaker was actually on fell outside the candidate range, so it could never catch up — the highlight locked in place and stopped moving. The follower now runs a cheap coarse match across the whole document every update and, when a block well outside the neighborhood clearly out-scores the current one for several updates running, re-anchors to it. The cursor can no longer get stuck behind the speaker.

1.2.12026-07-12

Fixed

  • Sermon Follower no longer flip-flops between similar adjacent paragraphs (e.g. during an altar call, where several paragraphs repeat the same refrain with small variations). Plain cosine similarity scored those near-duplicate blocks almost equally — the shared words dominated — so the highlight bounced between them. The follower now scores discriminatively: among the blocks near the cursor, each shared word's weight is divided by how many of those blocks contain it, so the words that differ between the similar paragraphs decide which one is active. It also smooths scores over time (a challenger must lead the current block by a margin across several updates before the highlight moves, so a momentary match can't cause a jump) and weights recent words more heavily, so it tracks the paragraph being spoken now rather than one still lingering in the window. Still fully on-device.

1.1.52026-07-06

Fixed

  • Sermon Follower stops jumping around on repeated or ad-libbed words. The matcher was treating any recognized phrase as a command to relocate the cursor, so a word the speaker repeated (but that's only written a couple of times, e.g. "bedrock") kept yanking the highlight to one of those written spots. The aligner is redesigned around continuity: it now tracks contiguously — advancing in small steps as the speaker reads and simply ignoring anything it can't place nearby (ad-libs no longer move it) — and only makes a larger jump (catch-up, skip, or recovery) on a unique, exact 4-word phrase. 1.1.42026-07-05

Fixed

  • Sermon Follower no longer freezes near the top while the speaker is well into the message.
